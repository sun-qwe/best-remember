# 每周蒸馏：可复制的提示词

> 每周一次，10 分钟。**这是整套东西唯一需要你动脑的环节**，其它都自动。
> 复制下面分隔线之间的内容，发给任意一个能读文件的工具（DSH / Claude Code / Cursor 都行）。

---

读这个仓库里的三个文件，然后给我一份 diff 建议。**不要直接改任何文件**，只输出建议。

1. `inbox.md` —— 我这一周攒下的新事实
2. `journal/` 里最近 7 天的条目 —— 我实际做过什么
3. `me/preferences.md`、`me/identity.md`、`me/environment.md` —— 现有的长期档案

请按这个格式回我：

## 一、建议合并（每条给出：目标文件 + 原文 + 改成什么）
只收有长期价值的。一次性的、会过期的、我已经写过的不算。

## 二、冲突（必须单列）
`inbox` 或 `journal` 里有没有和现有 `me/` 写反的？列出来，
每条要我明确回答一个二选一：**改 `me/`** 还是 **只针对某类情况例外**。
不许自己替我决定，也不许悄悄合进去。

## 三、建议删除
`me/` 里有没有已经三个月没被用到、或者明显不再成立的条目？列出来。

## 四、保留但不动
简要列一下你认为还是对的，一句话带过。

最后告诉我：这周有没有出现"反复出现的同一个诉求"？如果有，它可能该升格成一条硬约束。

---

## 你的动作（就两个）

1. 对「二、冲突」逐条回答 A/B
2. 说一句「按建议改」，然后自己 `git commit`

## 为什么必须人工确认

AI 自己改自己读的规则，会形成自我强化循环：它误判一次你的偏好 → 写进 `me/` →
下次它照着错的理解干活 → 又"验证"了这个误判。三周后你得到一份很自信的错档案。
**捕获可以自动，改长期档案不能自动。**
